# ผู้ช่วย AI — และเส้นที่ห้ามข้าม

AI ในระบบนี้มีหน้าที่เดียว: **ช่วยคนอ่าน** ไม่ใช่ช่วยคนตัดสิน

---

## ทำไมถึงต้องมี

ผู้ตรวจที่มีบันทึกการเรียน 100 ครั้งอ่านไม่ไหว สุดท้ายจึงไม่อ่านเลย
และครั้งที่สำคัญจริงก็หลุดไป — สรุปสั้นๆ ที่ชี้ว่าครั้งไหนผิดปกติ คือสิ่งที่ทำให้กองนี้ตรวจได้จริง

อีกงานหนึ่งคือชี้ข้อสอบที่นำเข้าจาก PDF แล้วข้อความไทยเพี้ยน คนอ่านภาษาไทยเห็นปุ๊บรู้ทันที
แต่ regular expression ไม่มีวันจับได้ — ตรงกับข้อจำกัดที่บันทึกไว้ใน [PDF import](../README.md)

## เส้นที่ห้ามข้าม

บังคับไว้ในโค้ด ไม่ใช่ฝากไว้กับวินัยของผู้เรียก เพราะพลาดแล้วคือเหตุการณ์ละเมิดข้อมูล ไม่ใช่บั๊ก

### 1. ไม่มีข้อมูลชีวมิติออกไป

โมเดล **ไม่เห็น**: ภาพนิ่ง คลิป ค่า embedding คะแนน similarity คะแนน liveness ชื่อไฟล์ หรือ userid

โมเดล **เห็นเฉพาะ**: จำนวนผลตรวจแยกตามผลตัดสิน (`identity:pass` 3 ครั้ง) ชื่อเหตุการณ์และจำนวนครั้ง
ระยะเวลา สถานะการจบ และ snapshot ของนโยบาย — ซึ่งทั้งหมดพิมพ์อยู่บนหน้ารายงานอยู่แล้ว

payload สร้างจาก **whitelist** ไม่ใช่การตัดฟิลด์ออก — ถ้าเพิ่มคอลัมน์ใหม่ในตารางวันหลัง
มันจะไม่ไหลออกไปเองโดยไม่มีใครตัดสินใจ มีเทสต์ตรวจ payload จริงว่าไม่มีคำต้องห้ามหลุด

> เอกสารความยินยอมบอกผู้เรียนว่าข้อมูลใบหน้าไปที่บริการที่ไม่เก็บอะไรไว้
> การส่งไปโมเดลภาษาแทนจะทำให้ประโยคนั้นเป็นเท็จ

### 2. AI ไม่ตัดสินอะไร

คำสั่งที่ให้โมเดลระบุชัด และมีเทสต์อ่าน prompt เพื่อกันไม่ให้ใครลบทิ้งเงียบๆ:

- ห้ามบอกหรือบอกเป็นนัยว่าผู้เรียนทุจริต หรือไม่ทุจริต
- ห้ามแนะนำให้ผ่าน ไม่ผ่าน หรือลงโทษใคร
- ถ้าบันทึกไม่มีอะไรผิดปกติ ให้บอกตรงๆ ไม่ใช่หาเรื่องมาเติม
- ถ้าข้อมูลน้อยเกินจะสรุป ให้บอกว่าน้อยเกินไป

ผลลัพธ์ถูกแสดงเป็น **"ร่างสรุป"** พร้อมข้อความกำกับว่าไม่ใช่ข้อสรุป โมเดลไม่ได้เห็นภาพ
และไม่มีส่วนตัดสิน — การตัดสินยังอยู่กับกติกาและกับคน

### 3. ปิดไว้เป็นค่าเริ่มต้น

ไม่มีส่วนไหนของระบบพึ่งพา AI ปิดอยู่แล้วทุกอย่างทำงานครบเหมือนเดิม
และถ้า gateway ล่ม หน้าจอจะบอกว่าล่ม ไม่ใช่เงียบแล้วปล่อยให้ผู้ตรวจคิดว่าไม่มีอะไรจะสรุป

## สถาปัตยกรรม

```
LMS ของลูกค้า ──POST /summarise──> AI reviewer service ──> โมเดล
 (Moodle plugin)   payload ตาม        (ของเรา ดูแลเอง)      Ollama บนเครื่องเรา
                   contract 1.0        · ตรวจ payload         หรือ GPT-5 mini
                                       · ถือ prompt ทั้งหมด
                                       · ตรวจคำตอบก่อนส่งออก
```

ดูสัญญาการเชื่อมต่อเต็มที่ [AI-CONTRACT.md](AI-CONTRACT.md)

### ทำไมต้องแยกเป็นบริการ

ตอนที่ prompt และกฎเรื่อง payload อยู่ในปลั๊กอิน มันทำงานได้ดีตราบใดที่เราถือทั้งสองฝั่ง
แต่ดีลนี้ลูกค้าเอาซอร์สไปดูแลเอง — กฎก็กลายเป็นของเขาที่แก้ได้ payload ก็ของเขาที่ขยายได้
ในขณะที่สรุปที่ออกมายังมีชื่อเราติดอยู่ และเรายังต้องรับสายเวลามันพัง

พอย้ายมาเป็นบริการ ประโยคเดิมเปลี่ยนความหมายไปเลย:

| | ก่อน | หลัง |
|---|---|---|
| "ไม่มีข้อมูลชีวมิติออกไป" | วินัยของผู้เรียก | โค้ดใน `contract.py` |
| ผู้เรียกส่งผิด | รั่วเงียบๆ | `422` พร้อมชื่อฟิลด์ |
| ลูกค้าแก้ schema ตัวเอง | AI พัง เราโดนโทษ | ไม่กระทบ |
| ใครลบ guardrail ได้ | ใครก็ได้ที่แก้ปลั๊กอิน | เราเท่านั้น |

**ขอบเขตความรับผิดชอบชัด** — เราดูแลบริการ ลูกค้าดูแล LMS ซึ่งเป็นรูปแบบเดียว
ที่สัญญาดูแลรายเดือนมีความหมาย

### กฎที่บังคับด้วยรูปทรงของข้อมูล

`checks` `events` `evidence` รับเฉพาะ**จำนวนเต็ม** — และคะแนน similarity, liveness,
confidence **เป็นทศนิยมทั้งหมด** ฉะนั้น payload ปฏิเสธค่าเหล่านั้นเองโดยไม่ต้องเดาชื่อฟิลด์

เป็นกฎเดียวที่ทนต่อการเปลี่ยนชื่อฟิลด์เพื่อเลี่ยงตัวกรองคำ

### ตรวจคำตอบ ไม่ใช่แค่ตรวจคำถาม

**วัดจริงกับ qwen2.5:7b: คำสั่งห้ามตัดสินใน prompt เอาอยู่แค่ 1 ใน 5 ครั้ง**
โมเดลเขียนประโยคทำนอง *"ยังไม่มีหลักฐานชัดเจนว่าเกิดจากการกระทำผิด"* ซ้ำๆ
ซึ่งคือคำพิพากษาที่เขียนในรูปการปฏิเสธ และผู้ตรวจก็อ่านมันแบบนั้น

คำสั่งที่โมเดล "ทำตามเกือบทุกครั้ง" ไม่ใช่การรับประกัน จึงย้ายไปบังคับที่ `guard.py`
ซึ่งอ่านข้อความที่กลับมาจริง ถ้าเจอคำพิพากษาจะถามใหม่หนึ่งครั้ง ยังเจออยู่ก็ตอบ
`guardrail_violation` แทน — **ผู้ตรวจไม่มีวันได้เห็นสรุปที่ตัดสิน**

การล้มเหลวดังๆ คือพฤติกรรมที่ตั้งใจ ถ้าโมเดลที่เลือกเขียนสรุปโดยไม่ตัดสินไม่ได้
ผู้ดูแลต้องรู้ว่าโมเดลนั้นไม่เหมาะกับงานนี้ ไม่ใช่ได้อ่านคำตัดสิน

### LiteLLM

[LiteLLM](https://github.com/BerriAI/litellm) (MIT) ยังอยู่ใน profile `ai` สำหรับกรณี
ที่ต้องต่อผู้ให้บริการหลายเจ้าหรือทำ budget/rate limit แต่**ไม่จำเป็นแล้ว** —
บริการพูด OpenAI-compatible ตรงๆ จึงต่อ Ollama ได้โดยไม่ต้องมีอะไรคั่นกลาง

### ทำไมไม่ใช้ agent framework

LangGraph, CrewAI, AutoGen เหมาะกับงานที่ agent ต้องเรียกเครื่องมือหลายขั้นและตัดสินใจเอง
งานที่นี่คือ "สรุปตัวเลขชุดนี้" และ "ข้อความนี้เพี้ยนไหม" — เรียก chat completion ครั้งเดียวจบ

การใส่ framework เข้ามาตอนนี้คือเพิ่มน้ำหนักโดยไม่ได้อะไร ถ้าวันหนึ่งมีงานที่ต้องเรียกเครื่องมือ
หลายขั้นจริง ค่อยพิจารณาใหม่

## เปิดใช้งาน

บริการขึ้นมาพร้อม stack ปกติ ไม่ต้องใช้ profile:

```bash
docker compose up -d ai-service
```

ค่าเริ่มต้นชี้ไปที่ **Ollama บนเครื่องที่รัน Docker** ด้วยโมเดล `qwen2.5:7b-instruct`
เปลี่ยนได้ที่ `.env`:

```
AI_LLM_BASE_URL=http://host.docker.internal:11434/v1
AI_LLM_MODEL=qwen2.5:7b-instruct
```

ฝั่ง Moodle เปิดที่ Site administration → Plugins → Local plugins →
KAISER Proctor → ผู้ช่วย AI (ปิดเป็นค่าเริ่มต้น)

**ก่อนชี้ไปที่โมเดลบนคลาวด์** ต้องตรวจว่าการส่งข้อมูลกิจกรรมผู้เรียนออกนอกองค์กร
อยู่ในขอบเขตของเอกสารความยินยอมและสัญญาประมวลผลข้อมูลแล้ว ถ้ายังไม่ครอบคลุม
ให้ใช้โมเดลบนเครื่องต่อไป ซึ่งเป็นค่าเริ่มต้นอยู่แล้ว

## วัดแล้วได้อะไร และอะไรที่ยังไม่รู้

เทสต์ของบริการ 20 ตัว (`ai-service/tests/`) รันได้โดยไม่ต้องมีโมเดล เพราะสิ่งที่ตรวจคือ
ขอบเขต ไม่ใช่คุณภาพ อีก 6 ตัวใน `tests/test_13_ai_assistance.py` ตรวจทั้งเส้นทางจาก Moodle

### สรุปรายครั้ง — ใช้ได้กับโมเดลบนเครื่อง

qwen2.5:7b เขียนสรุปภาษาไทยที่อ่านรู้เรื่องและตรงกับตัวเลข หลังใส่ตัวตรวจคำตอบแล้ว
สรุปที่ส่งถึงผู้ตรวจไม่มีคำพิพากษาปนใน 8 จาก 8 ครั้งที่ทดสอบ

### ตรวจข้อความไทยเพี้ยน — **ยังใช้ไม่ได้กับโมเดลบนเครื่อง**

จับข้อที่เสียจริงได้ 6/6 ครั้ง แต่**ฟ้องข้อที่สะอาดผิดด้วย 6/6 ครั้ง**

ฟีเจอร์นี้มีไว้ชี้ให้คนไปดูเฉพาะจุด ถ้าฟ้องทุกข้อ คนก็ต้องอ่านทั้งหมดอยู่ดี = ไม่มีประโยชน์
ต้องทดสอบกับ GPT-5 mini ก่อนเปิดใช้จริง และถ้ายังไม่ดีขึ้นก็ควรปิดฟีเจอร์นี้ไว้
ส่วนสรุปรายครั้งใช้ได้ตามปกติ

ผลดิบอยู่ที่ `reports/ai-model-comparison.txt`, `reports/ai-repeatability.txt`,
`reports/ai-guardrail-check.txt`

### ที่ยังไม่ได้ประเมิน

**คุณภาพสรุปในเชิงว่ามันช่วยผู้ตรวจได้จริงไหม** ยังไม่มีใครวัด — ต้องให้ผู้ตรวจจริง
อ่านสัก 10–20 ครั้งแล้วบอกว่าอ่านแล้วประหยัดเวลาหรือเปล่า เทสต์บอกได้แค่ว่ามันไม่ทำสิ่งต้องห้าม
