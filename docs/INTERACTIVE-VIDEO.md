# วิดีโอแบบมีปฏิสัมพันธ์ — `mod_kaivideo`

เขียนเอง ไม่ได้ยืมมา

---

## ทำไมต้องเขียนเอง ทั้งที่ของเดิมใช้ได้

`mod_interactivevideo` (ของ Sokunthearith Makara, GPL-3) ทำงานได้ดี และเคยติดตั้งอยู่ข้างๆ
เพื่อเทียบกัน — ถอดออกแล้วเมื่อของเราครอบคลุมการใช้งานที่ต้องการครบ
สิ่งที่มันเป็นไม่ได้ตั้งแต่แรกคือ **เป็นของเรา**

ลูกค้าต้องตรวจสอบทั้งสามชิ้นที่ซื้อไป ปลั๊กอินของบุคคลที่สาม*อ่านได้* แต่เรา*รับผิดชอบแทนไม่ได้*
เราสัญญาวันแก้บั๊กบน issue tracker ของคนอื่นไม่ได้ และเมื่อลูกค้าถามว่า "ตรงนี้ทำงานยังไง"
คำตอบที่ว่า "ต้องไปอ่านโค้ดของอีกทีม" ไม่ใช่คำตอบของคนขาย

จึงเลือก **ทำของเล็กกว่าให้ครบถ้วน** แทนการห่อของใหญ่กว่า

| | `mod_interactivevideo` | `mod_kaivideo` |
|---|---|---|
| ผู้เขียน | Sokunthearith Makara | KAISER |
| ชนิด player | 22 แบบ | **ไฟล์อัปโหลด + ไฟล์ตรง + HLS + YouTube + Vimeo** |
| ชนิดคำถาม | หลายสิบแบบ | 4 แบบ (ตอบข้อเดียว / ตอบหลายข้อ / พิมพ์คำตอบ / ข้อความ) |
| เราแก้เองได้ | ❌ | ✅ |
| ลูกค้าตรวจแล้วถามเราได้ | ❌ | ✅ |

**ยังเล็กกว่ามาก** และตารางนี้อยู่ที่นี่เพื่อให้ตัดสินใจได้ ไม่ใช่เพื่อขาย

## ที่ตั้งใจแยกเหมือน face recognition

face-service แยกส่วนที่เป็น**ข้อมูลและการตัดสิน** ออกจากส่วนที่เป็น**หน้าจอ** ที่นี่ก็เหมือนกัน:

```
classes/timeline.php    คำถามอยู่ตรงไหนบนไทม์ไลน์      ← ตรวจได้โดยไม่ต้องมีเบราว์เซอร์
classes/responses.php   ตรวจคำตอบ ให้คะแนน บันทึก      ← ตรวจได้โดยไม่ต้องมีเบราว์เซอร์
amd/src/player.js       เล่นวิดีโอและแสดงคำถาม          ← ส่วนเดียวที่ต้องเป็น UI
```

การตรวจว่าตอบถูกหรือผิดเกิดที่ `responses.php` **ที่เดียว** เบราว์เซอร์รู้ผลหลังจากส่งคำตอบไปแล้ว
ไม่เคยอยู่ในฐานะที่จะตัดสินเอง

---

## กฎสามข้อที่บังคับด้วยโค้ด

### 1. เฉลยไม่เคยออกไปที่เบราว์เซอร์ก่อนตอบ

`timeline::for_player()` ส่งเฉพาะ `questiontext` กับ `choices`
ส่วน `answers` (เฉลย) และ `feedback` ไม่มีอยู่ใน payload เลย

คำถามแบบ **พิมพ์คำตอบ** เป็นกรณีที่พลาดได้ง่ายที่สุด เพราะเฉลยเป็น "คำ" ไม่ใช่ตัวเลข
ถ้าหลุดไปก็จะอ่านเหมือนข้อความธรรมดาในหน้าเว็บ เทสต์จึงค้นหาคำที่ยอมรับทุกคำในหน้า HTML จริง
ไม่ได้ดูแค่ว่าไม่มีคีย์ชื่อ `answers`

คำถามแบบ **ข้อความ** ไม่มีเฉลยให้ปิด — เนื้อหาทั้งหมดคือตัวข้อความ จึงส่ง `feedback` ไปได้เลย

ไทม์ไลน์ที่มีเฉลยติดไปด้วยไม่ใช่การประเมิน แต่คือข้อสอบที่พิมพ์เฉลยไว้หลังกระดาษ
และไม่มีความระมัดระวังฝั่ง JavaScript ระดับไหนแก้เรื่องนี้ได้

มีเทสต์อ่าน HTML ของหน้าจริงเพื่อยืนยัน — ไม่ใช่อ่าน API เพราะคนที่จะโกงเปิด developer tools

### 2. ลากแถบเวลาข้ามคำถามไม่ได้

วิธีที่นึกออกก่อนคือดักตอนหัวเล่น "ข้าม" เวลาที่ตั้งไว้ — และเป็นวิธีที่ผิด เพราะลากแถบเวลา
ข้ามไปได้เลย

**คำถามถือว่าถึงกำหนดเมื่อหัวเล่นอยู่ที่หรือเลยจุดนั้นแล้วและยังไม่ได้ตอบ** ทำให้การเล่นปกติ
การลากแถบ และการกลับมาเรียนต่อ กลายเป็นกรณีเดียวกันหมด และไม่เหลือช่องให้เลี่ยง

### 3. ตอบผิดแล้วยังไม่เห็นเฉลย ถ้ายังมีสิทธิ์ตอบใหม่

เจอตอนทดสอบจริง: ตอบผิด → เห็นคำอธิบาย → กด "ลองใหม่" → ตอบถูกฟรี
**นั่นไม่ใช่การให้โอกาสตอบใหม่ แต่เป็นปุ่มแจกคะแนน**

ตอนนี้ถ้าตอบผิดและยังตอบใหม่ได้ เซิร์ฟเวอร์ไม่ส่งทั้งเฉลยและคำอธิบายกลับมา
พอตอบถูก หรือหมดสิทธิ์ตอบใหม่ จึงปล่อยออกมา — เพราะคำอธิบายคือเหตุผลทั้งหมดของการถามกลางบทเรียน

## ที่มาของวิดีโอ 4 แบบ

| แบบ | เล่นด้วยอะไร | ใช้เมื่อ |
|---|---|---|
| อัปโหลดเข้า Moodle | `<video>` | ผู้สอนมีไฟล์ ไม่มีที่วาง |
| ไฟล์ตรง (MP4/WebM) | `<video>` | มีที่วางไฟล์อยู่แล้ว |
| **HLS (.m3u8)** | `<video>` + video.js | สตรีมหลายความละเอียด หรือของเดิมอยู่บน CDN |
| YouTube / **Vimeo** | iframe + API ของเจ้าของ | วิดีโออยู่ที่นั่นอยู่แล้ว |

**HLS ถูกที่สุดในสี่แบบ** เพราะเล่นใน `<video>` ปกติ โดยให้ video.js ต่อสตรีมเข้ากับ element
— และ Moodle มี video.js พร้อม `@videojs/http-streaming` (Apache-2.0) มาให้อยู่แล้ว
ไม่ต้องเอาไลบรารีเข้ามาเอง ไม่ต้องพึ่ง CDN และไม่มีเรื่องสัญญาอนุญาตใหม่
ทุกอย่างที่อยู่ถัดจากนั้น — ปุ่มควบคุม กฎคำถามถึงกำหนด ตัวเฝ้าดูการคุมสอบ — แยกไม่ออกว่าเป็น HLS

**Vimeo ไม่ได้ซ่อนปุ่มควบคุมของตัวเอง** สั่งให้ซ่อนได้ก็จริง แต่จะได้ผลหรือไม่ขึ้นกับบัญชีที่วิดีโอนั้นอยู่
และการรับประกันที่ใช้ได้เฉพาะบางบัญชีของลูกค้าไม่ใช่การรับประกัน จึงใช้วิธี**วางแผ่นใสทับ iframe**
ให้เอื้อมไม่ถึงแทน ปุ่มของเราอยู่ข้างล่างเหมือนเดิม

**Vimeo ที่ตั้ง unlisted ต้องมี hash** — `vimeo.com/123456789/abcdef1234` ระบบเก็บ hash ไว้ด้วย
เพราะถ้าไม่มี ตัวเล่นจะไม่ยอมโหลด และวิดีโอ unlisted คือแบบที่ลูกค้าใช้วางคอร์สที่เก็บเงิน
ถ้าทิ้ง hash ฟีเจอร์นี้ก็จะใช้ได้เฉพาะวิดีโอที่ไม่มีใครต้องการมันตั้งแต่แรก

### ที่มาของวิดีโอ: อัปโหลด หรือใส่ที่อยู่

| | อัปโหลดเข้า Moodle | ใส่เป็นที่อยู่ |
|---|---|---|
| ใครดูได้ | เฉพาะคนที่ลงทะเบียนในคอร์ส | ใครก็ตามที่รู้ที่อยู่ (ถ้าที่นั่นไม่ได้จำกัด) |
| สำรองข้อมูลคอร์ส | ✅ ไฟล์ติดไปด้วย | ❌ ไปแค่ที่อยู่ |
| ออกอินเทอร์เน็ตไม่ได้ | ✅ ยังเล่นได้ | ❌ |
| พื้นที่ดิสก์ | ใช้ | ไม่ใช้ |
| YouTube / Vimeo / HLS | ❌ | ✅ |

**เก็บได้อย่างเดียว** ไม่มีคอลัมน์ที่บอกว่า "อันนี้ใช้ไฟล์อัปโหลด" เพราะคอลัมน์แบบนั้นขัดแย้งกับ
ความจริงได้ (ไฟล์หายแต่คอลัมน์ยังบอกว่ามี) แล้วกิจกรรมจะพังในแบบที่ฟอร์มแสดงให้เห็นไม่ได้
**ตัว file area คือความจริง** — `source::url()` คืนไฟล์ถ้ามี ไม่มีจึงค่อยใช้ที่อยู่
และตอนบันทึก ฝั่งที่ไม่ได้เลือกจะถูกล้างทิ้ง

ไฟล์ส่งผ่าน `pluginfile.php` ซึ่งตรวจการลงทะเบียนก่อน ไม่ใช่แค่ตรวจว่าล็อกอินแล้ว
เพราะที่อยู่ที่เล่นได้สำหรับทุกคนที่มีบัญชีคือที่อยู่ที่จะถูกส่งต่อ

## คำถาม 4 ชนิด และเหตุผลของแต่ละข้อ

| ชนิด | ผู้เรียนทำอะไร | ตรวจอย่างไร |
|---|---|---|
| `choice` | เลือก 1 ข้อ | กดข้อไหนคือคำตอบทันที ไม่มีปุ่มส่ง |
| `multichoice` | ติ๊กได้หลายข้อ แล้วกดส่ง | ต้องครบทุกข้อที่ถูก และห้ามเกิน |
| `shorttext` | พิมพ์เอง | เทียบกับรายการที่ผู้สอนกำหนด |
| `info` | อ่านแล้วกดต่อ | ไม่ตรวจ ไม่มีคะแนน |

**`multichoice` ไม่มีคะแนนบางส่วน** ให้ครึ่งคะแนนเมื่อติ๊กถูกครึ่งหนึ่งฟังดูใจดี แต่เปิดข้อโต้แย้ง
เรื่องเกณฑ์ที่ทั้งผู้เรียนและผู้สอนตัดสินจากบันทึกไม่ได้ และทำให้คนที่ติ๊กทุกข้อยกเว้นข้อยากได้เท่ากับ
คนที่เข้าใจคำถามจริง

**`shorttext` ให้อภัยเฉพาะช่องว่างและตัวพิมพ์ใหญ่เล็กภาษาอังกฤษ** ไม่ตัดวรรณยุกต์หรือสระไทยออก
เพราะการถือว่า ผู้ กับ ผู เป็นคำเดียวกันคือการยอมรับคำที่สะกดผิด ไม่ใช่การผ่อนปรน
ถ้าต้องการรับคำที่เขียนต่างออกไป ผู้สอนเพิ่มเป็นอีกบรรทัด — การตัดสินอยู่กับคนที่รู้เนื้อหา

**`info` มีอยู่เพราะเป็นสิ่งที่ผู้สอนอยากทำมากที่สุดและไทม์ไลน์ของคำถามล้วนแสดงไม่ได้:**
หยุด พูดอะไรสักอย่าง แล้วเล่นต่อ ถ้าไม่มีชนิดนี้ ผู้สอนจะเขียนคำถามที่มีคำตอบชัดเจนข้อเดียวแทน
ซึ่งเป็นสิ่งเดียวกันในรูปแบบที่แย่กว่า

`info` **ไม่อยู่ในตัวหารของคะแนน** — การอ่านข้อความไม่ใช่คำถาม ถ้านับด้วยจะดันคะแนนทุกคนขึ้น
ตามจำนวนข้อความที่ผู้สอนบังเอิญใส่ไว้

แต่ `info` **อยู่ใน "ตอบครบทุกข้อ" ของเงื่อนไขจบกิจกรรม** — เพราะเงื่อนไขนั้นพูดถึงการเดินผ่าน
วิดีโอจนครบ และข้อความคือจุดหยุดหนึ่งบนเส้นทางนั้น ถ้าไม่นับ ผู้เรียนจะจบกิจกรรมได้
โดยไม่เคยไปถึงสิ่งที่ผู้สอนตั้งใจหยุดมาบอก

## เข้ากับอีกสองชิ้นได้ทันที

**การคุมสอบไม่ต้องเขียนอะไรเพิ่มเลย** เพราะ player เป็น `<video>` element จริง และ
`video_adapter.js` ขับ `<video>` ธรรมดาได้อยู่แล้ว สิ่งที่ต้องทำมีแค่เพิ่ม `kaivideo`
เข้าไปในรายการกิจกรรมที่เฝ้าดูได้

นี่คือเหตุผลที่ตั้งใจไม่ใช้ iframe embed: player ที่ต้องคุยผ่าน postMessage
สั่งหยุดให้ตรงจังหวะที่คำถามถึงกำหนดไม่ได้จริง และเฝ้าดูก็ยากกว่ามาก

**ผู้ช่วยนำทางหาเจอเอง** เพราะเป็นกิจกรรมธรรมดาในคอร์ส ไม่มี special case ที่ไหน

## บั๊กที่เกือบหลุดไป

ผมประกาศ `FEATURE_BACKUP_MOODLE2 => true` แล้วไม่ได้เขียนคลาส backup

ผลคือ **การสำรองข้อมูลคอร์สไหนก็ตามที่มีกิจกรรมนี้อยู่ พังทั้งคอร์ส** ด้วย
`Class "backup_kaivideo_activity_task" not found` — ฟีเจอร์แกนกลางพังเพราะกิจกรรม
ที่ทำงานได้ปกติทุกอย่าง และไม่มีอะไรในพฤติกรรมของตัวมันเองที่จะบอกได้

เจอเพราะ**ลองสำรองข้อมูลจริง** ไม่ใช่เพราะอ่านเอกสาร ตอนนี้มี backup/restore ครบ
และมีเทสต์ round-trip ถาวรที่ตรวจว่าคำถามและคำตอบกลับมาครบ

## ที่ยังไม่มี

พูดให้ชัดเพื่อไม่ให้ใครไปสัญญาผิด:

| | สถานะ |
|---|---|
| YouTube | ✅ ผ่าน IFrame API |
| Vimeo | ✅ ผ่าน Player SDK รองรับ unlisted ที่มี hash |
| HLS (.m3u8) | ✅ ผ่าน video.js ที่ Moodle มีอยู่แล้ว |
| DASH / PeerTube | ❌ |
| คำถามชนิดอื่น | ✅ ตอบข้อเดียว / ตอบหลายข้อ / พิมพ์คำตอบ / ข้อความ |
| จับคู่ ลากวาง เติมคำในช่องว่างกลางประโยค | ❌ |
| หน้ารายงานสำหรับผู้สอน | ✅ แยกตามคำถามและตามผู้เรียน |
| เงื่อนไขจบกิจกรรม | ✅ ตอบครบทุกข้อ / ดูจนจบ |
| อัปโหลดไฟล์วิดีโอเข้า Moodle | ✅ หรือจะใส่เป็น URL ก็ได้ |
| backup / restore | ✅ |
| Privacy API (ขอดู/ขอลบ) | ✅ |
| สมุดคะแนน | ✅ สัดส่วนข้อที่ตอบถูก |

ข้อที่ควรทำต่อเป็นอันดับแรกตอนนี้คือ **คำถามแบบจับคู่หรือลากวาง** ซึ่งเป็นชนิดที่ผู้สอนถามหาบ่อยที่สุด
ในบรรดาชนิดที่ยังไม่มี

### ข้อควรรู้ก่อนขาย Vimeo

Vimeo จะไม่ยอมให้ฝังวิดีโอบนเว็บที่ไม่ได้อยู่ในรายการที่อนุญาตของวิดีโอนั้น โดยตอบกลับเป็น 401

รุ่นแรกของเราค้างที่ "loading" ตลอดไป เป็นกล่องเปล่าโดยไม่มีอะไรอธิบาย ซึ่งคือสิ่งที่ลูกค้า

## หน้ารายงานผู้สอน

`/mod/kaivideo/report.php?cmid=` (ต้องมีสิทธิ์ `mod/kaivideo:viewreport`)

**ตารางแยกตามคำถามมาก่อน และเรียงจากข้อที่ยากที่สุด** เพราะรายงานที่เรียงตามเวลา
จะฝังปัญหาไว้กลางตาราง ส่วนตารางแยกตามผู้เรียน — ตัวที่ทุกคนขอ — บอกแค่ว่าบางคนทำได้ดีกว่าบางคน
ซึ่งผู้สอนรู้อยู่แล้ว

*"18 จาก 20 คนเลือกข้อ 3 ในคำถามนาทีที่ 04:12"* ไม่ใช่ข้อเท็จจริงเกี่ยวกับ 18 คนนั้น
แต่เป็นข้อเท็จจริงเกี่ยวกับวิดีโอสี่นาทีก่อนหน้านั้น และเป็นสิ่งเดียวในหน้านี้ที่บอกได้ว่าต้องไปแก้อะไร

จึงมีป้ายเตือนบนข้อที่คนส่วนใหญ่ตอบผิด และแสดง**คำตอบผิดที่คนเลือกมากที่สุด**
ซึ่งมักคือความเข้าใจผิดที่ต้องอธิบาย ไม่ใช่คำถามที่เขียนกำกวม

## เงื่อนไขจบกิจกรรม

"เข้าดูแล้ว" เป็นค่าเริ่มต้นของ Moodle และแทบไร้ความหมายที่นี่ — เปิดวิดีโอแล้วปิด ไม่ใช่การเรียน

มีสองกฎ แยกกันเพราะพลาดกันคนละแบบ: คนที่ตอบครบทุกข้อแต่หยุดกลางห้านาทีสุดท้าย
กับคนที่ปล่อยวิดีโอเล่นในแท็บอื่นจนจบแล้วไม่ตอบอะไรเลย

**"ตอบครบทุกข้อ" นับที่การตอบ ไม่ใช่การตอบถูก** — คนที่ไล่ดูจนจบทั้งวิดีโอถือว่าทำกิจกรรมแล้ว
ส่วนตอบถูกกี่ข้อเป็นเรื่องของคะแนน

> เจอบั๊กตอนเขียนเทสต์: ผมไม่ได้เขียน `kaivideo_get_coursemodule_info()` ซึ่งเป็นที่ที่
> core อ่านว่ากิจกรรมนี้มีกฎอะไรเปิดอยู่ ผลคือช่องติ๊กโผล่ในฟอร์ม บันทึกได้ปกติ
> แล้ว**ไม่ถูกประเมินเลย** — กฎที่เงียบๆ ไม่ทำงาน แย่กว่ากฎที่พังให้เห็น

## สอง backend และความต่างที่ไม่ใช่เรื่องความสวยงาม

```
classes/source.php     ที่อยู่นี้เป็นไฟล์หรือ YouTube และ id คืออะไร
amd/src/backend.js     ห่อทั้งสองให้หน้าตาเหมือน <video> element
amd/src/player.js      ไม่รู้จักเลยว่าข้างล่างเป็นอะไร
```

| | ไฟล์ตรง (MP4/WebM) | YouTube |
|---|---|---|
| หยุดวิดีโอ | ทันทีในจังหวะเดียวกัน | ข้าม postMessage — ไม่ทันที |
| อ่านตำแหน่งหัวเล่น | อ่านตรงๆ | poll ทุก 250 มิลลิวินาที |
| การคุมสอบ | adapter ขับได้เลย | ผ่าน `window.KAIVIDEO` |

**ไฟล์ตรงดีกว่า** และเขียนไว้ที่นี่แทนที่จะให้คนไปเจอเองตอนคำถามมาช้าไปครึ่งวินาที
แต่ลูกค้าส่วนใหญ่มีวิดีโออยู่บน YouTube แล้ว และการบอกให้เขาย้ายไปโฮสต์ใหม่ไม่ใช่คำตอบจริง

### ปุ่มควบคุมเป็นของเรา ไม่ใช่ของ player

**ปิด native controls ของ YouTube ทั้งหมด** ไม่ใช่เพื่อความเรียบร้อย แต่เพราะถ้าเปิดไว้
ผู้เรียนลากแถบเวลาและกดเล่นต่อจาก*ข้างใน iframe* ได้ ซึ่งเป็นที่ที่โค้ดของเราเข้าไปขวางไม่ได้
และประโยคที่ว่า "วิดีโอจะไม่เล่นผ่านคำถามที่ยังไม่ตอบ" จะกลายเป็นสิ่งที่เราพูดไม่ได้อีก

จึงมีแค่ เล่น / หยุด / ถอย 10 วิ — **ไม่มีปุ่มกระโดดไปข้างหน้า** เพราะปุ่มที่กระโดดไปข้างหน้า
คือปุ่มสำหรับข้ามคำถาม

`window.KAIVIDEO` ประกาศ interface กลาง (play / pause / currentTime / isPaused)
จึงเฝ้าดูบทเรียน YouTube หรือ Vimeo ได้โดยที่ตัวเฝ้าดูไม่ต้องรู้จักผู้ให้บริการเลย
