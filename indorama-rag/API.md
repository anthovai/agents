# Agent API

ผู้ช่วยตอบคำถามเชิงระบบเกี่ยวกับ LMS จาก schema, routing table และโครงสร้างซอร์สโค้ด
ที่ index ไว้จากไฟล์ export

เอกสารนี้สำหรับ**ผู้ที่จะเรียกใช้ API** ส่วนเรื่องการติดตั้งและการ build index อยู่ใน
[README.md](README.md)

---

## หลักการที่บริการนี้บังคับใช้เอง

ไม่ใช่แค่ขอไว้ใน prompt แต่บังคับในโค้ด เพราะโมเดลทำถูกเกือบทุกครั้ง
และครั้งที่ผิดคือครั้งที่สำคัญ

- **คำถามนอกขอบเขตไม่ถูกส่งไปหาโมเดลเลย** ตัดสินก่อน retrieval จะทำงาน
- **ค้นไม่เจอ = ไม่เรียกโมเดล** โมเดลที่ได้คำถามโดยไม่มีเอกสารประกอบจะตอบอยู่ดี
  จากสิ่งที่มันเคยเรียนมาเรื่องแอป CodeIgniter ทั่วไป — และคำตอบนั้นอธิบายระบบอื่น
  ไม่ใช่ระบบนี้
- **ตอบได้เฉพาะสิ่งที่ถูกป้อนให้** ไม่ใช่ทุกอย่างที่มีใน corpus แต่คือเฉพาะเอกสาร
  ของคำถามนั้น คำตอบที่เอ่ยชื่อตารางที่ไม่ได้ถูกป้อนให้จะถูกทิ้ง (`ungrounded_answer`)
- **ห้ามคำนวณเลขเอง** ทุกตัวเลขต้องปรากฏในเอกสารหรือในคำถาม
  เคยเจอ: โมเดลได้รายการที่เขียนว่า "26 ตาราง" แล้วคัดลอกรายการออกมา นับของตัวเองใหม่ และรายงาน 22
- **sources คือ chunk จริงที่ถูกป้อนให้โมเดล** ไม่ใช่การอ้างอิงที่โมเดลเขียนขึ้นเอง
  ผู้อ่านจึงตรวจคำตอบกับ schema ได้ ไม่ใช่ตรวจกับความทรงจำ

**บริการนี้เห็นแต่โครงสร้าง ไม่เห็นข้อมูลในตารางแม้แต่แถวเดียว** ตอบไม่ได้ว่ามีใครอยู่ในระบบบ้าง
หรือข้อมูลของใครเป็นอะไร ถามแบบนั้นจะได้คำตอบว่าตอบไม่ได้

## การยืนยันตัวตน

ทุก endpoint ยกเว้น `GET /health` และ `GET /` ต้องส่ง header:

```
X-Agent-Key: <RAG_API_KEY>
```

ผิดหรือไม่ส่ง → `401 {"detail": "invalid_api_key"}`

### ⚠️ กุญแจนี้ต้องไม่หลุดถึงผู้ใช้ปลายทาง

กุญแจบอกว่า**ระบบไหน**เรียกมา ไม่ได้บอกว่า**ใคร**ถาม ผู้เรียกส่ง `user_id` มาเอง
และบริการนี้เชื่อตามนั้น เพราะไม่มีทางตรวจสอบ — และการสร้างระบบบัญชีขึ้นมาตรวจ
ก็แปลว่าต้องเก็บรหัสผ่านของคนที่มีบัญชีอยู่ที่อื่นแล้ว

แปลว่า **ใครถือกุญแจ อ่านและลบบทสนทนาของ `user_id` ใดก็ได้ที่เดาชื่อถูก**
ถูกต้องสำหรับ backend ที่เรียกแทนผู้ใช้ของตัวเอง และผิดสำหรับทุกอย่างนอกจากนั้น

- ✅ backend ของคุณ → เรียกบริการนี้ พร้อมกุญแจ
- ❌ browser / mobile app → **ห้าม** ถือกุญแจ

`user_id` ควรเป็นรหัสภายในที่คงที่ ไม่ใช่ชื่อหรืออีเมล เช่น `crm_88421`

### จำนวนครั้งที่เรียกได้

`/chat` และ `/ask` มีเพดานต่อกุญแจ ค่าตั้งต้น **20 ครั้งต่อนาที** และยิงติดกันได้
**10 ครั้ง** หลังจากเงียบไปพักหนึ่ง เกินแล้วได้

```
429  {"detail": "rate_limited"}     พร้อม header  Retry-After: <วินาที>
```

**ให้รอตามที่ `Retry-After` บอก อย่า retry ทันที** — การ retry ทันทีคือพฤติกรรม
ที่ทำให้โควตาหมดตั้งแต่แรก

โควตาแยกตามกุญแจ กุญแจของคุณหมดไม่กระทบผู้เรียกรายอื่น และกุญแจผิดที่ยิงเข้ามา
ไม่กินโควตาของใครเลย

`/search`, `/health` และ endpoint บทสนทนาไม่มีเพดาน เพราะไม่เรียกโมเดล

## `POST /chat` — ถามหนึ่งเทิร์น (endpoint หลัก)

```bash
curl -s localhost:9200/chat \
  -H "X-Agent-Key: $RAG_API_KEY" \
  -H "content-type: application/json" \
  -d '{"user_id": "crm_88421", "message": "ตาราง tbl_company เก็บอะไร"}'
```

| ฟิลด์ | จำเป็น | ความหมาย |
|---|---|---|
| `user_id` | ✅ | รหัสผู้ใช้ฝั่งคุณ ใช้แยกบทสนทนา |
| `message` | ✅ | คำถาม |
| `conversation_id` | — | ส่งกลับมาเพื่อคุยต่อในบทเดิม ไม่ส่ง = เริ่มบทใหม่ |

```json
{
  "ok": true,
  "conversation_id": "ec31d29b1458445d",
  "answer": "ตารางนี้ใช้เก็บข้อมูลเกี่ยวกับบริษัท ...",
  "sources": ["tbl_company"],
  "tool_calls": [
    {"tool": "get_table", "arguments": {"name": "tbl_company"},
     "found": true, "sources": ["tbl_company"]}
  ],
  "lists": [
    {"ref": "tbl_company", "title": "ตาราง tbl_company",
     "text": "ตาราง tbl_company (schema dbo) — 35 คอลัมน์ ...", "kind": "table"}
  ]
}
```

**เก็บ `conversation_id` ไว้แล้วส่งกลับมาในคำถามถัดไป** ไม่งั้นทุกคำถามเริ่มบทใหม่
และผู้ช่วยจะไม่รู้ว่า "ตารางนี้" หมายถึงอะไร

**`answer` เป็นร้อยแก้ว ไม่มีชื่อตาราง/คอลัมน์/path อยู่ในประโยค** — ตั้งใจให้เป็นแบบนั้น
ชื่อจริงอยู่ใน `sources` และ `lists` ซึ่งมาจากผลของ tool ตรงๆ ไม่ได้ผ่านการพิมพ์ซ้ำของโมเดล
ชื่อที่โมเดลไม่ได้พิมพ์ คือชื่อที่โมเดลพิมพ์ผิดไม่ได้

**แสดง `lists` ข้างคำตอบ** เป็นรายการที่ผู้อ่านตรวจได้ ถ้าแสดงแต่ `answer` อย่างเดียว
ผู้อ่านจะได้คำอธิบายโดยไม่มีของจริงให้ตรวจ

`tool_calls` มีไว้ให้ดูว่าผู้ช่วยไปดูอะไรมาบ้าง มีประโยชน์ตอน debug — ไม่ต้องแสดงให้ผู้ใช้เห็น

## `POST /ask` — ถามครั้งเดียว ไม่มีบทสนทนา

ค้นครั้งเดียว เรียกโมเดลครั้งเดียว ไม่มี tool ไม่มีความจำ เร็วกว่าและคาดเดาได้มากกว่า

```bash
curl -s localhost:9200/ask \
  -H "X-Agent-Key: $RAG_API_KEY" \
  -H "content-type: application/json" \
  -d '{"question": "ตาราง tbl_quiz มีคอลัมน์อะไรบ้าง"}'
```

ใช้เมื่อคำตอบจาก `/chat` ดูผิด แล้วอยากรู้ว่าปัญหาอยู่ที่การค้นหรือที่ agent loop
ต่างจาก `/chat` ตรงที่ **คำตอบเอ่ยชื่อทางเทคนิคได้** เพราะไม่มี agent guard เรื่องชื่อ

## `POST /search` — ค้นอย่างเดียว ไม่มีโมเดล

```bash
curl -s localhost:9200/search \
  -H "X-Agent-Key: $RAG_API_KEY" \
  -H "content-type: application/json" \
  -d '{"query": "company", "limit": 5}'
```

คืน chunk ที่ตรงพร้อมคะแนน ไม่เรียกโมเดลเลย เร็วมาก
เหมาะกับการทำ autocomplete หรือช่องค้นหา schema ในระบบฝั่งคุณ

## บทสนทนา

| endpoint | ทำอะไร |
|---|---|
| `GET /conversations?user_id=` | รายการบทสนทนา + พื้นที่ที่ใช้ |
| `GET /conversations/{id}?user_id=` | บทสนทนาเป็นเทิร์นๆ |
| `GET /conversations/{id}?user_id=&raw=true` | ไฟล์ Markdown ดิบ |
| `PATCH /conversations/{id}` | เปลี่ยนชื่อ — body: `{"user_id": "...", "title": "..."}` |
| `DELETE /conversations/{id}?user_id=` | ลบบทเดียว |
| `DELETE /conversations?user_id=X&confirm=X` | ลบทั้งหมดของคนนั้น (ต้องส่ง user_id ซ้ำใน `confirm`) |

บทสนทนาเก็บเป็นไฟล์ Markdown บนดิสก์ `raw=true` คืนไฟล์นั้นตรงๆ — เอาออกไปได้จริง
ซึ่งเป็นความหมายส่วนใหญ่ของคำว่าเป็นเจ้าของข้อมูล

โควตา 1 GB ต่อ `user_id` (ปรับที่ `RAG_USER_QUOTA_BYTES`) เกินแล้ว**ปฏิเสธ ไม่ตัดทิ้ง** —
บทสนทนาที่หายไปครึ่งหนึ่งเงียบๆ แย่กว่าคำถามที่ถูกปฏิเสธพร้อมบอกเหตุผล

## `GET /health` — ไม่ต้องใช้กุญแจ

```json
{
  "ok": true,
  "chunks": 520,
  "model": "gpt-5-mini",
  "build": {"source_archive": "...", "source_sha256": "...", "chunks_by_kind": "..."}
}
```

`build` บอกว่า index สร้างจาก export ไฟล์ไหน พร้อม SHA-256 — ตรวจได้ว่าคำตอบ
มาจากข้อมูลชุดที่คุณคิดว่ามันมาจริงหรือเปล่า

`{"ok": false, "code": "no_index"}` = ยังไม่ได้ build index

## ผู้ช่วยสำหรับ "ผู้เรียน" — `/learner/*`

คนละ endpoint คนละคลังข้อมูลกับด้านบน และตั้งใจให้แยกกันจริง ไม่ใช่แค่ส่ง flag
ต่างกัน

คลังของ `/chat` และ `/ask` คือ schema, ชื่อตาราง, ชื่อ controller และ path
ของซอร์สโค้ด ส่วน export ของฝั่งผู้เรียนเขียนกติกาของตัวเองไว้ว่า
**ห้ามแสดงชื่อ controller, API, ตาราง หรือ path ให้ผู้เรียนเห็น** — index
เดียวถือทั้งสองอย่างแล้วรักษากติกานั้นไม่ได้ สองอันแยกกันทำผิดไม่ได้

`/learner/ask` **ไม่มี** tool loop และ**ไม่มี**บทสนทนา คำถามเดียว คำตอบเดียว
คนที่ถามว่า "มีหลักสูตรปฐมพยาบาลไหม" ไม่ได้กำลังคุยต่อเนื่อง

### `POST /learner/ask`

```bash
curl -X POST https://HOST/agent/learner/ask   -H 'X-Agent-Key: <คีย์ของคุณ>'   -H 'Content-Type: application/json'   -d '{"question": "มีหลักสูตรเกี่ยวกับการช่วยชีวิตฉุกเฉินไหม"}'
```

```json
{
  "ok": true,
  "answer": "มีครับ หลักสูตร ... ใช้เวลา ... ดูรายละเอียดได้ที่ https://...",
  "model": "gpt-5-mini",
  "sources": ["vajira-basic-life-support-2026", "digest_courses"],
  "lists": [{"ref": "...", "title": "...", "kind": "course", "text": "..."}]
}
```

| field | หมายถึง |
|---|---|
| `question` | คำถาม (รับ `message` ด้วย) — จำเป็น |
| `sources` | alias ของหลักสูตร/หน้าที่ถูกป้อนให้โมเดลจริง |
| `lists` | ตัวข้อความที่ป้อนให้โมเดล ตรวจคำตอบย้อนกลับได้ |

**ไม่มี** `user_id` และ `conversation_id` โดยตั้งใจ — endpoint นี้ไม่เก็บอะไรเลย

### สิ่งที่ endpoint นี้ตอบไม่ได้ และไม่ใช่บั๊ก

- **"ฉันเรียนจบไปกี่หลักสูตรแล้ว" / "ฉันได้กี่คะแนน"** — export ไม่มีข้อมูล
  รายบุคคลเลย (ไม่มี profile, ไม่มี enrollment, ไม่มีคะแนน) ผู้ช่วยจะบอกตรง ๆ
  ว่าไม่มีข้อมูล แล้วชี้หน้าที่ผู้เรียนเปิดดูเองได้ ระบบฝั่งคุณคือฝ่ายที่รู้เรื่องนั้น
  ไม่ใช่ผู้ช่วยตัวนี้
- **ชื่อตาราง/API/โค้ด** — ถ้าอยากถามเรื่องพวกนี้ ใช้ `/chat` กับคีย์ของฝั่ง
  developer
- **คำถามนอกเรื่อง** เช่นดินฟ้าอากาศ ถูกปฏิเสธก่อนถึงโมเดลด้วย `off_topic`

### `GET /learner/health` — ไม่ต้องใช้กุญแจ

```json
{"ok": true, "chunks": 109, "model": "gpt-5-mini", "build": {"source_sha256": "..."}}
```

`{"ok": false, "code": "not_configured"}` = deployment นี้ยังไม่ได้ใส่ index
ฝั่งผู้เรียน (ตั้ง `RAG_LEARNER_INDEX_PATH`) ซึ่งไม่เหมือนกับ "ค้นไม่เจอ" —
อย่างแรกแก้ที่ไฟล์ env อย่างหลังแก้ที่คำถาม

## รหัสข้อผิดพลาด

ทุกความผิดพลาดคือ `{"ok": false, "code": "...", "detail": "..."}`

| code | สถานะ | หมายถึง | ควรทำอะไร |
|---|---|---|---|
| `invalid_api_key` | 401 | กุญแจผิดหรือไม่ได้ส่ง | ตรวจ `X-Agent-Key` |
| `off_topic` | 400 | คำถามไม่ได้เกี่ยวกับระบบนี้ | แสดง `detail` ให้ผู้ใช้ ไม่ต้อง retry |
| `no_material` | 404 | เกี่ยวกับระบบ แต่ไม่มีอะไรใน index ตรง | บอกผู้ใช้ให้ระบุชื่อตาราง/หน้าให้ชัดขึ้น |
| `ungrounded_answer` | 400 | โมเดลตอบสิ่งที่ตรวจสอบไม่ได้ คำตอบถูกทิ้ง | retry ได้ 1 ครั้ง ถ้ายังไม่ได้ให้แจ้งผู้ใช้ |
| `empty_question` / `no_user` | 422 | ไม่ได้ส่ง `message` หรือ `user_id` | บั๊กฝั่งผู้เรียก |
| `llm_timeout` | 502 | โมเดลใช้เวลาเกิน `RAG_AGENT_TIMEOUT` | คำถามแรกหลังเงียบนานจะช้าเพราะโหลดโมเดล — retry |
| `llm_unreachable` | 502 | ต่อโมเดลไม่ได้ | ตรวจว่า Ollama/backend รันอยู่ |
| `llm_error` / `llm_malformed` / `llm_empty` | 502 | โมเดลตอบผิดรูปหรือว่างเปล่า | retry ได้ |
| `quota_exceeded` | 413 | `user_id` นั้นใช้พื้นที่เต็มโควตา | ให้ผู้ใช้ลบบทสนทนาเก่า |
| `no_such_conversation` | 404 | ไม่มี `conversation_id` นี้ของ `user_id` นี้ | เริ่มบทใหม่ |
| `rate_limited` | 429 | เรียกถี่เกินเพดานของกุญแจนี้ | รอตาม `Retry-After` แล้วค่อยยิงใหม่ |
| `not_configured` | 503 | deployment นี้ไม่มี index ฝั่งผู้เรียน (`/learner/*` เท่านั้น) | ตั้ง `RAG_LEARNER_INDEX_PATH` แล้ว restart |
| `not_confirmed` | 400 | `DELETE /conversations` ไม่ได้ส่ง `confirm` ให้ตรง | ส่ง `confirm` เท่ากับ `user_id` |

`off_topic`, `no_material`, `ungrounded_answer` **ไม่ใช่บั๊ก** — เป็นการทำงานตามที่ออกแบบ
ระบบฝั่งคุณควรแสดงข้อความให้ผู้ใช้เข้าใจ ไม่ใช่แสดงว่า "ระบบขัดข้อง"

## เรื่องเวลา

หนึ่งเทิร์นของ `/chat` คือการเรียกโมเดลหลายครั้ง (เลือก tool → อ่านผล → บางครั้งเรียกใหม่
หลังโดน guard) ปกติ **20–60 วินาที** บนเครื่องที่วัดไว้

- ตั้ง timeout ฝั่งผู้เรียกให้**มากกว่า** `RAG_AGENT_TIMEOUT` (ตั้งต้น 300 วิ)
  ไม่งั้นจะได้ timeout เปล่าๆ แทนคำอธิบายว่าส่วนไหนล้มเหลว
- **คำถามแรกหลังบริการเงียบไปนานจะช้าราว 60–70 วินาที** เพราะ Ollama ต้องโหลดโมเดล
  เข้าหน่วยความจำใหม่ ตั้ง `OLLAMA_KEEP_ALIVE=-1` ที่ฝั่ง Ollama เพื่อตัดปัญหานี้
- ควรทำ UI ที่แสดงว่ากำลังคิดอยู่ ไม่ใช่ปล่อยให้ค้าง

## ตัวอย่างการต่อ (PHP)

```php
$payload = ['user_id' => 'crm_' . $userId, 'message' => $question];
if ($conversationId !== '') {
    $payload['conversation_id'] = $conversationId;
}

$ch = curl_init($base . '/chat');
curl_setopt_array($ch, [
    CURLOPT_POST => true,
    CURLOPT_POSTFIELDS => json_encode($payload, JSON_UNESCAPED_UNICODE),
    CURLOPT_HTTPHEADER => [
        'Content-Type: application/json',
        'X-Agent-Key: ' . $apiKey,
    ],
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_TIMEOUT => 330,     // มากกว่า RAG_AGENT_TIMEOUT
]);
$result = json_decode(curl_exec($ch), true);

if (!empty($result['ok'])) {
    $answer         = $result['answer'];
    $conversationId = $result['conversation_id'];  // เก็บไว้ใช้เทิร์นถัดไป
    $lists          = $result['lists'];            // แสดงข้างคำตอบ
}
```

ดูตัวอย่างที่ใช้งานจริงได้ที่ `moodle/plugins/local_kaiproctor/classes/rag_client.php`

## ก่อนขึ้นใช้งานจริง

**ตั้ง `RAG_API_KEY`** ไม่ตั้ง = ทุก endpoint เปิดให้ทุกคน รวมถึงการอ่านบทสนทนาของคนอื่น

**อย่าเปิดพอร์ตสู่อินเทอร์เน็ตตรงๆ** ถ้าต้องเรียกข้ามเครื่อง ให้อยู่หลัง reverse proxy
ที่ทำ TLS และจำกัด IP ต้นทาง กุญแจที่วิ่งผ่าน HTTP ธรรมดาคือกุญแจที่อ่านได้ระหว่างทาง

**ใช้โมเดลบนเครื่องตัวเอง** ค่าตั้งต้นชี้ไป Ollama บนเครื่อง host เพราะ corpus นี้คือ
แผนที่ฐานข้อมูลทั้งระบบ ถ้าเปลี่ยน `RAG_LLM_BASE_URL` ไปหาผู้ให้บริการภายนอก
ทุกคำถามและทุก chunk ที่ค้นเจอจะถูกส่งออกไปนอกองค์กร

**index ไม่ใช่ข้อมูลสด** สร้างจาก export ณ เวลาหนึ่ง `/health` บอก SHA-256 ของไฟล์นั้น
ถ้าฐานข้อมูลจริงเปลี่ยนโครงสร้าง ต้อง export และ build index ใหม่
