# Deliverables

สิ่งที่แยกออกมาเพื่อส่งมอบให้ลูกค้า แยกจากตัวผลิตภัณฑ์ kai-proctor

## face-recognition/

**เป็น git submodule** ชี้ไปที่ https://github.com/anthovai/face-recognition
ซึ่งเป็นรีโปที่ลูกค้าได้รับจริง อยู่แยกกันเพราะลูกค้า clone รีโปนั้นตรงๆ
และไม่ควรได้อะไรที่ไม่ได้ตั้งใจส่งติดไปด้วย

clone รีโปนี้แล้วจะได้โฟลเดอร์ว่าง จนกว่าจะ

```bash
git submodule update --init deliverables/face-recognition
```

commit ของ submodule ที่ผูกไว้บอกว่า **ลูกค้าได้โค้ดเวอร์ชันไหนไป** ณ ตอนที่
repo หลักอยู่ในสภาพนี้ ซึ่งเป็นสิ่งที่ต้องตอบได้เวลาลูกค้าแจ้งปัญหา

บริการ Face Recognition แบบยืนตัวเดียวได้ — ตรวจจับใบหน้า ลงทะเบียน เทียบตัวตน
และตรวจภาพปลอม ไม่มีอะไรผูกกับ Moodle หรือระบบคุมสอบ

แยกมาจาก `face-service/` โดยตัดสิ่งที่ไม่ใช่ face recognition ออก คือ endpoint
`/parse-questions` และโมดูลอ่าน PDF (`exam_pdf.py`, `pdf_text.py`) รวมถึง
`pdfminer.six` ที่ตามมาด้วย

**ส่งมอบเป็น source ทั้งชุด** ลูกค้าเป็นเจ้าของและแก้เองได้ ดังนั้นทุกอย่างที่อ้างถึง
ระบบภายในของเราถูกล้างออกแล้ว — ไม่มีคำว่า Moodle, kai-proctor, KAISER,
ชื่อลูกค้ารายอื่น หรือ path บนเครื่องเรา หลงเหลือในโค้ดหรือเอกสาร
ตัวแปรตั้งค่าใช้คำนำหน้า `FACE_*` และ header คือ `X-Face-Key` ล้วน
(ไม่รับ `PROCTOR_*` เดิม เพราะลูกค้าไม่เคยมี deployment แบบนั้นให้ต้องรองรับ)

ส่งมอบเป็นโฟลเดอร์นี้ทั้งก้อน (zip ได้เลย หรือ `git init` เป็น repo ของตัวเอง)
เอกสารสำหรับลูกค้าอยู่ที่ [face-recognition/README.md](face-recognition/README.md)

### ⚠️ ยังไม่ได้ระบุไลเซนส์ของโค้ด

`models/LICENSES.md` ครอบคลุมเฉพาะน้ำหนักโมเดล (MIT / Apache-2.0) **โค้ดที่เราเขียนเอง
ยังไม่มีไฟล์ LICENSE** ต้องตัดสินใจก่อนส่งว่าลูกค้าได้สิทธิ์อะไร — ซื้อขาด แก้ได้
ส่งต่อได้ไหม — แล้วใส่ไฟล์ LICENSE ตามนั้น ส่ง source โดยไม่บอกเงื่อนไข
แปลว่าเถียงกันทีหลังโดยไม่มีเอกสารตัดสิน

### ไฟล์ที่ใช้ร่วมกับ face-service

`app/face_engine.py`, `app/liveness.py` และเทสสามไฟล์ คัดลอกมาตรงๆ ไม่ได้แก้
ถ้าแก้ไฟล์เหล่านี้ที่ฝั่งใดฝั่งหนึ่ง ต้องคัดลอกไปอีกฝั่งด้วย ตรวจว่าตรงกันอยู่ไหมด้วย:

```bash
python deliverables/check-drift.py
```

`app/config.py` กับ `app/main.py` **ตั้งใจให้ต่างกัน** สคริปต์จึงไม่ตรวจสองไฟล์นี้
และไม่เทียบ docstring บนหัวไฟล์ เพราะฉบับลูกค้าอธิบายบริการที่ยืนเดี่ยว
ส่วนของเราอธิบายบริการที่อยู่หลัง Moodle — ถูกทั้งคู่ในที่ของมัน และไม่ใช่โค้ด

## interactive-video/

วิดีโอที่หยุดถามระหว่างทาง — Python (FastAPI) ฝั่งเซิร์ฟเวอร์ + JavaScript
ฝั่งเบราว์เซอร์ที่ไม่พึ่งไลบรารีใดเลย

**ของเราทั้งหมด ไม่มีโค้ดของบุคคลที่สาม** ตัวเล่นแยกมาจาก `mod_kaivideo` ในโปรเจกต์
นี้ ส่วน backend เขียนใหม่เป็น Python ให้เข้าชุดกับ face-service และ indorama-rag

เคยพิจารณาเอาของสำเร็จรูปมาแก้แล้วไม่เอา ด้วยเหตุผลเรื่องไลเซนส์:

| ตัวเลือก | ทำไมไม่เอา |
|---|---|
| **H5P** | content type เป็น MIT แต่ `h5p-php-library` ที่รันมันเป็น **GPL-3.0** และ "H5P" เป็นเครื่องหมายการค้าจดทะเบียน — แก้แล้วขายแบบปิดโค้ดไม่ได้ |
| **FrameTrail** | dual MIT/GPL ใช้ได้ แต่เน้น annotation ไม่มีระบบควิซ ต้องเขียนเพิ่มเองอยู่ดี |
| **parevo/interactive-video** | MIT แต่มี 2 ดาว 2 commits ยังไม่โตพอเอาไปขาย |

**สิ่งที่ต้องรู้:** ตัวเล่นต้องเป็น JavaScript เสมอ ไม่มีทางเลือก — เบราว์เซอร์รัน JS
ไม่รัน Python การหยุดวิดีโอแล้ววาดคำถามทับต้องเกิดในเบราว์เซอร์ H5P, FrameTrail
และ Kaltura ก็เป็น JS ทั้งหมดด้วยเหตุผลเดียวกัน Python ทำหน้าที่ที่มันทำได้ดีคือ
เก็บบทเรียน ตรวจคำตอบ และเก็บบันทึก

หลักการที่ทุกอย่างถูกจัดวางรอบมัน: **เฉลยไม่เคยออกจากเซิร์ฟเวอร์ไปหาผู้เรียน**
`Item` กับ `PublicItem` เป็นคนละคลาส และ endpoint สำหรับเล่นส่งได้แต่อย่างหลัง

เอกสารสำหรับลูกค้า: [interactive-video/README.md](interactive-video/README.md)

## Agent API

ตัว Agent ไม่ได้คัดลอกออกมา เพราะ `indorama-rag/` แยกจาก kai-proctor
อยู่แล้วตั้งแต่ต้น — คนละ compose คนละวงจรชีวิต ไม่มี import ข้ามกัน
ส่งมอบโฟลเดอร์ `indorama-rag/` ได้ทั้งก้อน

เอกสาร API สำหรับลูกค้า: [../indorama-rag/API.md](../indorama-rag/API.md)

**ตั้ง `RAG_API_KEY` ก่อนส่งมอบเสมอ** ถ้าไม่ตั้ง ทุก endpoint เปิดให้ทุกคน
รวมถึงการอ่านบทสนทนาของผู้ใช้คนอื่น
