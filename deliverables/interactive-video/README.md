# Interactive Video Service

วิดีโอที่หยุดถามระหว่างทาง — ตอบถูกจึงจะดูต่อได้

> **ซอร์สโค้ดเปิดเผย แต่ไม่ใช่โอเพนซอร์ส** อ่าน ตรวจสอบ และทดลองรันได้เสรี
> ส่วนการ**ใช้งานจริงเชิงพาณิชย์ต้องมีข้อตกลง** และ**ห้ามส่งต่อหรือขายซ้ำ**
> ทุกกรณี — อ่าน [LICENSE](LICENSE) ก่อนใช้งาน

**Python (FastAPI) + JavaScript ไม่พึ่งเฟรมเวิร์กใด** ฝั่ง server เก็บบทเรียน
ตรวจคำตอบ และเก็บบันทึก ฝั่งเบราว์เซอร์เล่นวิดีโอและตัดสินว่าเมื่อไรควรถาม

---

## 🔑 หลักการที่ทุกอย่างถูกจัดวางรอบมัน

**เฉลยไม่เคยออกจากเซิร์ฟเวอร์ไปหาผู้เรียน**

timeline ที่ส่งให้ตัวเล่นถูกตัดเฉลยและ feedback ออกเสมอ ผู้เรียนที่เปิด
network tab ดูจะเห็นแค่คำถาม ไม่เห็นเกณฑ์การตรวจ — นี่ไม่ใช่เรื่องที่ค่อยไป
รัดกุมทีหลังที่ฝั่งหน้าเว็บได้ แต่ตัดสินที่นี่ครั้งเดียวด้วยการ**ส่งคนละอ็อบเจ็กต์**

ผลที่ตามมาคือ**การตรวจคำตอบเกิดที่เซิร์ฟเวอร์เสมอ** คำตัดสินที่หน้าเว็บคำนวณเอง
คือคำตัดสินที่หน้าเว็บถูกสั่งให้ตอบอะไรก็ได้

## กุญแจ 2 ใบ ทำคนละหน้าที่

| กุญแจ | header | ทำอะไรได้ |
|---|---|---|
| **player** | `X-Video-Key` | ดึง timeline (ไม่มีเฉลย), ส่งคำตอบ, อ่านผลของผู้ใช้คนนั้น |
| **admin** | `X-Video-Admin-Key` | สร้าง/แก้บทเรียน (ซึ่งมีเฉลยอยู่), อ่านผลทุกคน, ลบข้อมูลรายบุคคล |

กุญแจ admin ใช้แทน player ได้ แต่ไม่ใช่ทางกลับกัน

### ⚠️ กุญแจทั้งสองใบต้องไม่อยู่ในเบราว์เซอร์

บริการนี้รับ `user_id` มาจากผู้เรียกและ**เชื่อตามนั้น** เพราะตรวจสอบไม่ได้ —
ใครถือกุญแจ player จึงตอบคำถามในนามใครก็ได้ ส่วนกุญแจ admin คือเฉลยทั้งหมด

```
ผู้ใช้ → backend ของคุณ (ถือกุญแจ + รู้ว่าใครล็อกอินอยู่) → บริการนี้
```

## API

### เขียนบทเรียน — `PUT /videos/{id}` (admin)

```json
{
  "title": "ความปลอดภัยเบื้องต้น",
  "provider": "file",
  "source": "https://example.com/safety.mp4",
  "must_answer": true,
  "allow_retry": true,
  "timeline": [
    {"id": "i1", "at": 10, "type": "info", "text": "บทเรียนนี้จะหยุดถามเป็นระยะ"},
    {"id": "q1", "at": 30, "type": "choice", "text": "สีใดหมายถึงอันตราย",
     "choices": ["เขียว", "แดง", "ฟ้า"], "answers": [1],
     "feedback": "แดงคือหยุด", "category": "สัญญาณ"},
    {"id": "q2", "at": 120, "type": "shorttext", "text": "อุปกรณ์ป้องกันศีรษะ",
     "answers": ["หมวกนิรภัย", "helmet"], "category": "อุปกรณ์"}
  ]
}
```

| `provider` | `source` คือ |
|---|---|
| `file` | URL ของไฟล์วิดีโอ |
| `hls` | URL ของ `.m3u8` |
| `youtube` | video id |
| `vimeo` | video id หรือ `id:hash` สำหรับวิดีโอ unlisted |

**ชนิดคำถาม 4 แบบ**

| type | ตอบยังไง | `answers` คือ |
|---|---|---|
| `choice` | เลือกข้อเดียว กดแล้วส่งเลย | index ข้อที่ถูก (ต้องมี 1 ข้อ) |
| `multichoice` | ติ๊กหลายข้อ แล้วกดส่ง | index ทุกข้อที่ถูก |
| `shorttext` | พิมพ์ตอบ | ข้อความที่ยอมรับ (กี่แบบก็ได้) |
| `info` | แค่อ่านแล้วกดต่อ | ไม่ต้องมี |

**บทเรียนที่ตอบถูกไม่ได้จะถูกปฏิเสธตั้งแต่ตอนบันทึก** — multichoice ที่ไม่มีข้อถูก
หรือ shorttext ที่ไม่มีคำตอบใดยอมรับ จะได้ `422 bad_item` แทนที่จะไปโผล่ตอน
ผู้เรียนคนแรกเจอแล้วถูกตัดสินว่าผิดทั้งห้อง

### เล่น — `GET /videos/{id}/play?user_id=...` (player)

```json
{
  "ok": true,
  "video": {"provider": "file", "source": "...", "must_answer": true, "allow_retry": true},
  "timeline": [{"id": "q1", "at": 30, "type": "choice", "text": "...", "choices": ["..."]}],
  "answered": [{"item_id": "i1", "correct": true}],
  "resume_at": 95.4
}
```

สังเกตว่า item ที่ได้มี **5 ฟิลด์เท่านั้น** ไม่มี `answers` ไม่มี `feedback`

### ตอบ — `POST /videos/{id}/answer` (player)

```json
{"user_id": "staff_001", "item_id": "q1", "response": "[1]"}
```

`response` เป็น JSON array ของ index สำหรับ choice/multichoice หรือข้อความที่พิมพ์
สำหรับ shorttext และเป็นสตริงว่างสำหรับ info

```json
{"ok": true, "correct": false, "may_retry": true, "answers": [], "feedback": "แดงคือหยุด"}
```

**`answers` จะว่างตราบใดที่ยัง retry ได้** — เพราะบอกเฉลยตอนนั้นคือการแจกคะแนนฟรี
ตัวเล่นจึงแสดงสิ่งที่ได้รับมาได้เลยโดยไม่ต้องตัดสินใจเอง

### รายงาน

| endpoint | สิทธิ์ | คืนอะไร |
|---|---|---|
| `GET /videos/{id}/result?user_id=` | player | ผลของคนนั้น + แยกตามหมวด |
| `GET /videos/{id}/report` | admin | ผลทุกคน เรียงคนที่ยังไม่เสร็จขึ้นก่อน |
| `DELETE /users/{user_id}` | admin | ลบคนนั้นออกจากทุกบทเรียน |

**การ์ด `info` ไม่นับเป็นคะแนน** — บันทึกว่าอ่านแล้ว แต่ไม่เข้าตัวหาร ไม่งั้นคะแนน
ทุกคนจะสูงขึ้นตามจำนวนข้อความที่ผู้เขียนใส่ ซึ่งเป็นตัวเลขที่ไม่เกี่ยวกับผู้เรียนเลย

## ฝั่งเบราว์เซอร์

```html
<link rel="stylesheet" href="browser/player.css">
<script src="browser/src/backends.js"></script>
<script src="browser/src/strings.js"></script>
<script src="browser/src/api.js"></script>
<script src="browser/src/player.js"></script>
```

```js
new InteractiveVideo.Player({
    mount: document.getElementById('lesson'),
    api: InteractiveVideo.createApi({baseUrl: '/api/video'}),  // endpoint ของคุณ
    strings: InteractiveVideo.strings.th,
    onFinished: function () { location = '/done'; }
});
```

`createApi` ยิงไป **backend ของคุณ** ไม่ใช่บริการนี้โดยตรง — backend เติมกุญแจแล้ว
forward ต่อ ดู `browser/src/api.js` ว่าต้องมี endpoint อะไรบ้าง (4 ตัว)

### กฎที่ทำให้ข้ามคำถามไม่ได้

คำถามจะขึ้นเมื่อ **playhead อยู่ที่หรือเลยจุดนั้นแล้ว และยังไม่ได้ตอบ** — ไม่ใช่
"ตอนวิ่งผ่าน" เพราะการลากแถบเวลาข้ามไปจะไม่ผ่านจุดนั้นเลย วิธีนี้ทำให้การ seek,
การ resume และการเล่นปกติเป็นกรณีเดียวกันหมด และไม่เหลือทางอ้อม

ด้วยเหตุนี้**ปุ่มควบคุมจึงเป็นของเรา ไม่ใช่ของ YouTube/Vimeo** — ถ้าใช้ปุ่มของเขา
ผู้เรียนจะ seek แล้วเล่นต่อจากในไอเฟรมได้ ซึ่งเป็นที่ที่โค้ดนี้เข้าไปห้ามไม่ได้

### ลองดู

```bash
cd browser && python -m http.server 8080
```

เปิด `http://localhost:8080/example/` — มีคำถาม 3 จุด ลองกดข้ามดูได้

ตัวอย่างนั้นตรวจคำตอบในหน้าเว็บเองเพื่อให้รันได้โดยไม่ต้องมี backend
**ห้ามทำแบบนั้นจริง** เพราะเฉลยจะอยู่ในหน้าเว็บ

## การตั้งค่า

| ตัวแปร | ค่าตั้งต้น | ทำอะไร |
|---|---|---|
| `VIDEO_API_KEY` | *(ว่าง = ปิดการตรวจ)* | กุญแจฝั่งผู้เล่น |
| `VIDEO_ADMIN_KEY` | *(ว่าง = ปิดการตรวจ)* | กุญแจฝั่งผู้เขียน/รายงาน |
| `VIDEO_DB_PATH` | `data/interactive-video.sqlite` | ที่เก็บคำตอบและความคืบหน้า |
| `VIDEO_RATE_PER_MINUTE` | `300` | จำนวนครั้งต่อนาทีต่อกุญแจ |
| `VIDEO_RATE_BURST` | `100` | ยิงติดกันได้กี่ครั้ง |
| `VIDEO_MAX_RESPONSE_CHARS` | `500` | ความยาวคำตอบแบบพิมพ์สูงสุด |

**กุญแจว่างทั้งคู่ = ไม่ตรวจสิทธิ์เลย** สะดวกตอนทดสอบบนเครื่องตัวเอง และผิด
ในทุกที่นอกจากนั้น เพราะบริการนี้ถือเฉลยของทุกบทเรียนที่มันเสิร์ฟ

## ข้อควรรู้ก่อนขึ้นใช้งานจริง

**การตรวจคำตอบแบบพิมพ์เทียบตรงตัว** ยกเว้นช่องว่างและตัวพิมพ์เล็กใหญ่ของอักษรละติน
**ไม่มีการตัดรูปวรรณยุกต์ไทย** เพราะจะทำให้ ผู้ กับ ผู เป็นคำเดียวกัน ซึ่งไม่ใช่
การผ่อนผัน แต่คือการนับคำผิดว่าถูก — ใส่รูปแบบที่ยอมรับได้หลายแบบใน `answers` แทน

**ไม่มีคะแนนบางส่วนใน multichoice** ต้องติดถูกทุกข้อและไม่เกิน — ครึ่งคะแนนสำหรับ
ครึ่งหนึ่งของช่องเปิดทางให้เถียงเรื่องเกณฑ์ที่ไม่มีใครตัดสินได้จากบันทึก

**เบราว์เซอร์บังคับลำดับ ไม่ได้ป้องกัน** คนที่ตั้งใจจะข้ามด้วย devtools ยังทำได้
สิ่งที่รับประกันได้คือ**คะแนนถูกตัดสินที่เซิร์ฟเวอร์เสมอ** — ข้ามได้ก็ไม่ได้คะแนน

**สำรอง volume `video-data`** ในนั้นคือคำตอบทั้งหมดที่ใครถูกตัดสิน
`docker compose down` ไม่แตะมัน แต่ `down -v` ลบทิ้ง
